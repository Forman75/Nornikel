# R&D-граф знаний горно-металлургической отрасли

Система систематизации R&D-знаний: автоматически строит граф знаний из
разрозненных документов (отчёты, статьи, протоколы) и позволяет (1) проверять,
не проводилось ли уже аналогичное исследование, (2) отвечать на сложные
технические вопросы на естественном языке со ссылками на источники,
(3) визуально показывать граф и пробелы в изученности.

## Проблема

В организации накоплены исследования по горно-металлургическим процессам,
рассеянные по файлам и головам сотрудников. Команды **повторяют уже сделанную
работу**, потому что не видят, что аналогичное исследование уже проводилось.
Ручной поиск ответов по разрозненным источникам медленный.

## Что делает система

- **Ingestion**: разбирает PDF/DOCX/PPTX, нормализует OCR-артефакты
  (восстановление температур `2600С→260°C`, десятичных запятых), режет на чанки,
  извлекает через YandexGPT сущности/связи/числовые условия в строгую
  pydantic-схему, грузит в граф Neo4j с дедупликацией по нормализованным ключам.
- **Проверка дублей**: под описание новой работы — векторный поиск похожих
  исследований, карточка «это уже исследовано» с источником, автором, годом.
- **Q&A**: вопрос на русском → разбор в intent → обход графа + векторный поиск
  по чанкам → синтез ответа со ссылками, группировкой по методу/году/географии.
- **Gap-анализ**: комбинации материал+процесс без связанного эксперимента.
- **Визуализация**: граф на Cytoscape.js, подсветка подграфа ответа, фильтры
  РФ/зарубеж, красный пунктир для противоречий (`CONTRADICTS`).

## Стек

- **LLM/эмбеддинги**: Yandex AI Studio (`yandexgpt`, `text-search-doc/query`, 256-dim)
- **Граф + вектор-индекс**: Neo4j 5.x / AuraDB (единая база, vector index на Chunk)
- **Backend**: FastAPI (Python, async), pydantic для валидации вывода LLM
- **Frontend**: React + Cytoscape.js (single-file, без сборки)

## Онтология

Узлы: Material, Process, Equipment, Condition (параметр/оператор/значение/единица —
отдельный узел), Experiment, Publication, Chunk, Expert, Facility, Finding.
Связи: USES_MATERIAL, REQUIRES_CONDITION, OPERATES_AT_CONDITION, PRODUCES_OUTPUT,
PRODUCED, DESCRIBED_IN, HAS_CHUNK, MENTIONS, VALIDATED_BY, CONTRADICTS, AUTHORED_BY.

## Запуск

```bash
pip install -r requirements.txt

# переменные окружения:
#   NEO4J_URI, NEO4J_USER, NEO4J_PASSWORD, YANDEX_API_KEY, YANDEX_FOLDER_ID

# 1. отобрать релевантные документы из архива в corpus/:
python pick_corpus.py "path/to/data" --copy 12

# 2. загрузить корпус в граф:
python run_ingest.py corpus/*.pdf corpus/*.docx

# 3. поднять веб-интерфейс:
uvicorn api:app --port 8000
# открыть http://localhost:8000
```

Режимы ingestion: `--dry-run` (без API, проверка парсинга), `--no-graph`
(экстракция без записи в граф, проверка качества).

## Ключевое нефункциональное требование

Точность извлечения чисел: числовые условия (концентрации, температуры) строго
типизированы и провалидированы pydantic; если единица измерения не указана в
тексте явно — условие не извлекается (лучше пропустить, чем ошибиться).
Каждый факт несёт источник, уровень достоверности и цитату из текста.

## Структура

```
extraction_schema.py   схема извлечения (сущности/связи/условия) + валидация
graph_loader.py        загрузка в Neo4j, дедупликация, провенанс
neo4j_schema.cypher    DDL: constraints, vector index, fulltext index
normalize.py           нормализация OCR (температуры, запятые, переносы)
ingest.py              загрузчики PDF/DOCX/PPTX
chunker.py             чанкинг (проза + таблицы)
yandex_client.py       клиент Yandex AI Studio (экстракция + эмбеддинги + чат)
run_ingest.py          оркестратор ingestion
query_orchestrator.py  Q&A, gap-анализ, проверка дублей
api.py                 FastAPI-бэкенд
static/index.html      фронтенд (React + Cytoscape)
pick_corpus.py         отбор корпуса из архива по релевантности
```

## Границы MVP

Не реализованы (только упоминаются): RBAC, дашборды руководителей, уведомления,
полная мультиязычность, полное версионирование фактов.
